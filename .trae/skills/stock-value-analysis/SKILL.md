# 个股价值分析 Skill（完整工作流）

> 本文件是分析工作流的**唯一权威定义**。`.claude/skills/run-stock-value-analysis/SKILL.md` 是调用入口（Claude Code 环境），内容以本文件为准。

按价值投资五步分析流程，对用户指定的股票进行全流程分析，严格按个股分析模板生成 Markdown 报告。

## 触发条件

"分析一下 {股票名称}"、"分析 {股票名称}"、"看看 {股票名称}"、"研究一下 {股票名称}"、"帮我分析 {股票名称}"

## 分析流程

严格遵循五步分析流程，**顺序不可颠倒**：

```
① 定性 → ② 定量 → ③ 估值 → ④ 排雷 → ⑤ 执行
```

每一步之间有明确的 go/no-go 决策点（看不懂→放弃；数字有假→放弃；不便宜→等待；有雷→放弃），详见 `06_价值分析框架/五步分析流程.md`。逐步调用 `02_分析工具集/` 对应前缀工具（01_定性/02_定量/03_估值/04_排雷/05_执行）。

用 TodoWrite 跟踪进度：数据获取 → 五步分析 → 报告生成 → 校验 → 提交，分解为明确的 todo 项。

## 输出规范

所有个股分析报告必须严格按 `06_价值分析框架/个股分析模板.md` 统一格式输出。

报告保存路径：`07_个股分析报告/{股票名称}-{代码}.md`
**港股代码后加 H**（如 `美团-03690H.md`），用于与 A 股代码区分。补充分析放 `07_个股分析报告/_补充分析/{名称}-{代码}[H]-{主题}.md`。

## 数据获取工作流

原则：**MCP 数据工具优先**（本环境已配置 TDX/iFinD，结构化、实时），WebSearch 兜底；并行发起查询，数据不足如实标注，**不可编造数字**。

### Step 1: 股票代码查找

优先使用 TDX `tdx_lookup_stock`：

- A股：`args: {"query": "{股票名称}", "range": "AG"}`
- 港股：`args: {"query": "{股票名称}", "range": "HK-GP"}`
- 美股：`args: {"query": "{股票名称}", "range": "US"}`

无 TDX 时 WebSearch 确认。A 股 6 位（沪 60/68、深 00/30、北交所 8/4 开头）；港股 5 位；美股 ticker。

### Step 2: 并行获取数据（一次调用中全部发出）

#### 2.1 实时行情（TDX quotes）
- A股：`args: {"code": "{代码}", "setcode": "0"}`
- 港股：`args: {"code": "{代码}", "setcode": "31"}`

#### 2.2 财务数据（iFinD）
- **A股**（`..._ifind-ds-stock-mcp` 的 `get_stock_financials`）：
  `{股票名称} {代码} 2021年 2022年 2023年 2024年 2025年 ROE ROA 毛利率 净利率 资产负债率 营收 营收增速 净利润 净利润增速 经营现金流 每股收益 每股净资产 每股股利 分红 现金分红`
- **港股**（`..._ifind-ds-globa` 的 `global_stock_financial`）：
  `{股票名称} {代码} 最新报告期 ROE ROA 毛利率 净利率 资产负债率 营收增速 净利润增速 经营现金流 自由现金流 每股收益 每股净资产 每股股利 分红数据`

#### 2.3 公司信息（iFinD profile/info）
- A股：`{股票名称} {代码} 公司基本信息 所属行业 上市日期 主营业务 业务构成 收入结构 公司简介`
- 港股：同上去掉"公司简介"亦可

#### 2.4 股东 + 估值分位 + 财务摘要（TDX deep_info，固定三查询）
`entity_type` 区分 `A股代码` / `港股代码`：
```
查询 {代码} {股票名称} 主要股东 股本结构 实际控制人 控股股东持股比例
查询 {代码} {股票名称} PE PB Band 历史估值分位 估值分析
查询 {代码} {股票名称} 财务摘要 盈利能力 成长能力 分红记录 营收构成
```

**数据源对照**：

| 数据源 | MCP Server | 主要用途 |
|--------|-----------|---------|
| 通达信 TDX | `mcp_..._plugin_tdx_tdx` | 实时行情、PE/PB Band、估值分位、股东结构、财务摘要 |
| 同花顺 iFinD (A股) | `mcp_..._ifind-ds-stock-mcp` | A股财务数据、公司信息、估值指标 |

美股：iFinD 全球版覆盖财务/信息，其余用英文 WebSearch 补（`{name} {ticker} earnings revenue net income 2021-2025`）。MCP 与 WebSearch 数据冲突时以**公告原文**为准。

### Step 3: 数据不全时补充查询

- **估值分位不完整** → 补 PE Band / PB Band 查询（PE、PB 分别查）
- **财务历史缺失** → 补 iFinD 年度数据查询；仍缺则 WebSearch（新浪财经/东方财富/港交所披露易）
- **股东信息不完整** → iFinD `get_stock_shareholders`，或查年报"股本变动及股东情况"
- **ESG/风险信息** → iFinD `get_esg_data` / `get_risk_indicators` / 天眼查风险标签
- **年报 PDF 原始三表** → 调用 `financial-report-extractor`（如环境提供）提取利润表/资产负债表/现金流量表

## 生成报告

数据收集完毕后，严格按模板结构生成。每条数据必须有来源标注，所有结论必须基于实际获取的数据。**分析类型判定**：根据公司特征判定为"价值投资/攒股收息/成长股/周期股/困境反转"之一，影响估值锚和评分维度。

**报告结构（12 章）**：
1. 核心数据面板（行情 + 估值 + 财务 + 分红）
2. L0 避坑筛选（7 类陷阱）
3. ① 定性：生意本质（定位 + 收入结构 + 护城河 + 股权 + 管理层 + 股票分类）
4. ② 定量：财务验证（营收利润趋势 + 现金流 + 资产负债 + 分红历史 + 会计排雷）
5. ③ 估值：选锚 + 定价（估值锚 + 绝对值 + 分位 + DDM + 交叉验证 + 可比公司）
6. ④ 排雷：风险识别（风险矩阵 + 价值陷阱 + 反叙事）
7. ⑤ 执行：仓位 + 时机 + 纪律（仓位 + 建仓 + 买入信号 + 卖出纪律）
8. 情景分析（三情景 + 概率加权）
9. 行业专属模块（根据行业选填银行/消费/制造/科技等）
10. 综合评分卡（通用 + 收息 + 同类对比）
11. 五步决策汇总
12. 数据来源

### 聂夫 TRR 参考公式（可选辅助，仅排序不作门槛）

> TRR = (盈利增长率 + 股息率) ÷ PE。TRR ≥ 2 标记为"聂夫合格"。仅作低市盈率候选池快速排序参考，不以它为 go/no-go 硬门槛；完整分析仍以五步流程为准。

### 泡沫识别模块（高估值/高情绪标的必做）

估值分位、盈利质量、增长可持续性触发高风险时，集成泡沫识别，判断绿色/黄色/橙色/红色泡沫等级。完整方法论见 `01_经典理论框架/14_泡沫识别与预警.md`。

**泡沫识别三确认（同时满足才定性"红色泡沫"）**：
1. 静态估值分位 > 95
2. 价值锚 V/M 显著 > 1.5
3. 盈利质量差（FCF/净利 < 1、ROE/ROIC 剪刀差）或行为过热（换手/杠杆/减持）

仅满足①的属"贵的成长股"而非泡沫，不可回避错杀优质标的。

### 格林沃尔德 EPV 估值框架（可选模块，价值投资型标的）

对盈利稳定、具有真实竞争优势（消费/OTC药/公用事业/品牌制造）的价值投资型标的，在模板"③ 估值"章节额外集成。完整方法论见 `01_经典理论框架/13_格林沃尔德-特许经营权估值法.md`。

**0️⃣ 前置判定：什么股票适合用 EPV（必须先行，不满足则不套用）**

EPV 硬前提：**假定盈利永续不变、不给增长付费**，乱套会严重低估成长股/高波动股：

| 维度 | 适合 EPV | 不适合 | 判定数据 |
|------|---------|--------|---------|
| 盈利稳定性 | 盈利中枢清晰、周期均值可靠 | 大起大落、亏损 | 5-10年净利/营业利润率标准差 |
| 增长依赖度 | 弱增长、成熟期、低增速 | 高成长需靠增长修复（赛道股） | 营收CAGR、再投资需求 |
| 资本密集度 | 轻资产、再投资需求极低 | 重资产强周期（煤炭钢铁峰值） | 维持性CAPEX/折旧 |
| 商业模式 | 消费/OTC药/公用事业/品牌制造/垄断媒体 | 银行保险等金融、高波动科技 | 行业属性 |
| 分红属性 | 攒股收息、稳定现金流 | 盈利不可持续 | 派息率、现金流覆盖 |

**判定三步法**：
1. **看 ROIC vs WACC**：ROIC 长期 > WACC 是"特许经营型企业"的前提（否则是资产型，应按 AV 估值）
2. **看增长/资本需求**：ROIC>WACC 但需持续大额再投资消化高增长（成长型）→ 必须叠加成长价值，不能只用 EPV 截断
3. **分类定锚**：银行/保险等金融 NOPAT 受资本充足率约束不可全分红，EPV 会高估可分配回报，应改用 DDM 或净资产锚；强周期股正常化盈利需做周期中枢校准且 WACC 上调

集成流程：
```
0️⃣ 适用性判定（先确认适合 EPV，不满足则退回常规估值）
① 定性分类（资产型/特许经营型/成长型）
② 正常化盈利校准 → 稳态 NOPAT
③ EPV/AV 估值 + 特许溢价倍数 EPV/AV
④ 三段式回报率 R_net = R_cash + R_organic + R_active − Fade
⑤ 对比 WACC，给出投资决策四档评级
```

**适用性判定写入报告"③ 估值"章节开头**：
```
### EPV 适用性判定
| 维度 | 结论 | 证据 |
|------|------|------|
| 企业类型 | 特许经营型/资产型/成长型 | ROIC,市场地位 |
| 盈利稳定性 | 高/中/低 | 5-10年净利标准差、营业利润率 |
| 增长依赖度 | 低/中/高 | 营收CAGR、再投资需求 |
| 资本密集度 | 轻/中/重 | 维护性CAPEX |
| WACC 区间 | X%-Y% | Beta、资产负债率、行业 |
| **判定** | ✅ 适用EPV / ⚠️ 需调整(DDM等) / ❌ 不套用 | 综合 |
```

**强制要求（防止框架误用）**：
1. **WACC 必须充分论证**：结合 Beta、资产负债率、行业属性给区间（消费股通常 6.5%-7.5%），不得随意取 8%；WACC 每变动 1% 结论可能翻转，需做敏感性提示
2. **正常化盈利必须说明口径**：ROIC 算法（是否剔除商誉/EV 口径）、主业增速基期（是否剔除并表扰动）必须透明披露——ROIC 不同算法可差 4-5pct，并表增速与有机增速可天壤之别
3. **Fade 衰减系数避免双重悲观**：已用有机增速测算内生回报时 Fade 应适度，避免"增速放缓"被重复扣减
4. **EPV/AV 交叉验证**：必须算特许溢价倍数 EPV/AV 确认特许价值真实存在；用 V/M 判断当前价格是否已充分定价
5. **与常规估值交叉对照**：EPV 结论必须与 PE/PB/股息率静态估值并列展示，说明分歧原因，不单一依赖某一方法下结论

## Troubleshooting

| 症状 | 解决 |
|---|---|
| `check` 报"数据来源章节缺失或过短" | 最后章节标题须含"数据来源"且其后有实质内容（>50 字符） |
| `check` 报"缺章节" | 对照模板 12 章补齐；刻意合并须在报告开头注明结构偏离 |
| `lint` 报断链/命名错误 | 重命名文件后未同步引用——`grep -rn "旧名称-旧代码" --include='*.md' .` 全库更新 |
| driver 报模块找不到 | 必须在仓库根目录运行（脚本按自身位置推导仓库根） |
